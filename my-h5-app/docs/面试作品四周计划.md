# 四周打磨计划：把项目做成能拿去面试实习的作品

> 创建日期：2026-10-04
> 目标：一个月内补上「实习作品集」的及格线三件套，并把话题面拓宽到后端核心领域
> 约束：时间约一个月 / 部署只用免费额度 / 后续精力优先投**后端深度**

---

## 一、判断标准：什么才算「拿得出手」

面试官评估实习生作品，本质上只看三件事：

| 判据 | 具体表现 | 当前状态 |
|---|---|---|
| **能不能用** | 有可访问的在线链接，面试官当场点得开 | ❌ 只有 localhost |
| **是不是真的** | 数据在真库里，有写操作，不是硬编码演示 | ❌ 硬编码数组，纯展示 |
| **讲不讲得清** | 每个技术选择能说出「为什么不选另一个、代价是什么」 | ✅ 已有 ADR-001/002 打底 |

前两条是**硬门槛**——缺了它们，第三条再好也会被归入「玩具项目」。这一个月的核心就是把前两条补齐。

---

## 二、现状盘点

### 已有资产（多数应届生没有，要主动讲）

- **ADR 决策记录**：ADR-001（依赖健康度）、ADR-002（双端方案）
- **依赖健康度审查**：发现 postcss fork 停更后主动写迁移预案 —— 面试官爱听的「主动性」故事
- **真实踩坑**：Safari 16.4 不认 `@media (width>=768px)`，导致 PC 样式静默降级
- **TypeScript 类型擦除 → 运行时校验**：能聊到语言本质，深度远超平均水平
- **依赖方向红线** `views→stores→api→utils`：有分层意识

### 致命短板（必被追问且当前答不上来）

1. **「数据存哪了？」** → `src/data/standings.ts` 是硬编码数组
2. **「能打开看看吗？」** → 无在线链接
3. **「用户能做什么操作？」** → 纯展示，触不到表单校验 / 权限 / 事务 / 并发

## 三、四周时间表

### 第 1 周 · 数据层：让后端真的连上数据库

| 事项 | 产出 | 面试话术点 |
|---|---|---|
| 安装 Prisma，写 `schema.prisma` | Team / Order / User 三张表 + 关系 | 「为什么用 ORM 而不是裸 SQL」 |
| 执行 migration | `migrations/` 版本化 SQL | 「迁移为什么要有版本号、回滚怎么做」 |
| 写 seed 种子脚本 | 一条命令灌满 20 支球队 | 「本地环境与 CI 怎么保证数据一致」 |
| `/standings`、`/order/list` 改查库 | 前端零改动即可跑 | 「接口契约不变，替换实现」 |

**为什么 SQLite 起步而不是 MySQL**：只是一个文件、零安装、本地能跑、部署也不挑；Prisma 换 MySQL 只改一行连接串，不影响简历写什么。先把「ORM + 迁移 + 建模」这套概念学会，数据库产品本身是次要的。

### 第 2 周 · 写操作闭环：让系统有「输入」

以现有 order 模块为载体做完整链路：

```
Vant Form 表单 → 前端校验（体验） → POST /order/create
   → 后端二次校验（安全） → 落库 → 返回 → 列表刷新
```

**这一周最值钱的一句话**：
> 前端校验是为了用户体验，后端校验是为了数据安全 —— 前端校验用 curl 直接打接口就能绕过。

配套产出：**ADR-003** 记录数据库与 ORM 选型理由与代价。

### 第 3 周 · 后端深度（重点投入）

| 事项 | 面试收益 |
|---|---|
| JWT 登录鉴权 + bcrypt 加密 | 被问频率最高的话题：token 存哪、怎么防 XSS、为什么不用 session、刷新策略 |
| Vitest 单元测试 + 接口测试 | 应届生里少数派；重点是给「校验逻辑」和「写操作」写用例 |
| GitHub Actions CI | push 即跑 lint + type-check + test，README 挂绿色 badge |

### 第 4 周 · 上线与包装

| 事项 | 说明 |
|---|---|
| 前端部署 Vercel / Netlify | 注意 hash 路由、API 地址走环境变量 |
| 后端部署 Render / Railway 免费层 | ⚠️ 风险见下 |
| README 重写为作品集格式 | 受众从「未来的自己」改为「面试官 30 秒扫读」 |

## 四、关键风险与预案

**风险 1：免费层的文件系统是临时的，SQLite 库可能被重置**
预案：部署时评估改用免费 PostgreSQL（Supabase / Neon 都提供免费额度，Prisma 只换 provider 和连接串）。
→ 这反而变成面试素材：「部署时发现 SQLite 在无状态容器里不可用，于是改成托管 PostgreSQL」——一次真实的环境问题处理经历。

**风险 2：一个月做不完就都只做一半**
预案：优先级已经排死，按 P0 → P1 顺序，**任何一周超时就砍 P2，绝不让 P0 缩水**。P0 四件事做完，这个月就算成功。

**风险 3：光做不讲**
预案：每完成一个模块，立刻补 ADR 或 README 的一句话说明。做完却讲不出所以然 = 白做。

---

## 五、建议的每周节奏

```
周一/周二   实操（写代码，附带找坑）
周三        写 ADR（把这一周的取舍固化成文档）
周四        继续实操 + 自测
周末        用「面试官视角」自问一遍：这个改动能引出什么问题？
```

最后一件事最重要：**做完要能讲**。真正拉开差距的不是功能多少，而是你能不能对一个技术选择说出「为什么不选另一个、代价是什么」。这也是我们一开始就养成的 ADR 习惯的价值所在。
