# ADR-005：数据层选型 —— MySQL 8 + MyBatis-Plus + Flyway，测试用 H2 同构

> 状态：已实施 ｜ 日期：2026-10-04 ｜ 关联：工程实施手册第 7、8 章

## 决策

| 位置 | 选择 | 理由 |
|---|---|---|
| 开发/生产库 | **MySQL 8**（本机已装 8.0.44） | 国内岗位主流；utf8mb4 建库 |
| 测试库 | **H2 内存库（MySQL 兼容模式）** | 任何机器/CI 可跑；与本地 MySQL 零干扰 |
| ORM | **MyBatis-Plus 3.5.16**（非最新 3.5.17） | 落后一小版本换社区验证时间 |
| 迁移 | **Flyway**（Boot 托管版本） | 表结构版本化，可复现 |

## 关键裁定

1. **同一份迁移脚本两边执行**：`V*.sql` 只用 MySQL 8 与 H2(MySQL 模式) 都支持的标准写法（不写 ENGINE/CHARSET 子句），保证「测的表结构 = 生产的表结构」。
2. **SQL 分工**：单表 CRUD 用 MP Wrapper；多表 JOIN 手写 XML（`OrderMapper.xml`）；MP 表达不了的 SQL 片段（如计算列排序）退回字符串是【有意识的交易】，用集成测试兜底。
3. **金额一律 INT 存分**：从 DDL 到 VO 全链路整数，杜绝浮点。

## 踩坑记录（实施中真实发生，都已写回代码注释）

1. **Connector/J 9.x 拒绝 `characterEncoding=utf8mb4`**：该参数要的是 Java 字符集名，只能写 `UTF-8`；utf8mb4 是 MySQL 侧字符集由建库保证。8.x 时代能容忍的写法在 9.x 直接启动失败。
2. **Hutool 的 BCrypt 在 `crypto.digest` 子包**：import `cn.hutool.crypto.BCrypt` 找不到符号。
3. **MP 3.5.9+ 分页插件拆包**：必须单独引 `mybatis-plus-jsqlparser`。
4. **LambdaQueryWrapper 表达不了计算列排序**：`(goals_for - goals_against)` 需退回 QueryWrapper 字符串列名。

## 迁移到生产（届时执行）

生产换托管 MySQL/PostgreSQL：改 `application-prod.yml` 数据源 + 环境变量；
若换 PostgreSQL 需检查 `V*.sql` 方言兼容性（当前脚本尽量用了标准 SQL，主要就是 AUTO_INCREMENT 要改 GENERATED IDENTITY）。
