# ADR-004：明知 EOL 仍选 Spring Boot 3.5（而不是 4.x）

> 状态：已拍板（用户确认接受取舍）｜ 日期：2026-10-04 ｜ 关联：ADR-001（依赖健康度复盘）

## 背景

搭建 Java 后端时，Spring Boot 版本线的事实（查证于 2026-10-04）：

- **4.x** 是当前活跃线（4.0 于 2025-11-20 发布），但换了 Jackson 3（包名从 `com.fasterxml` 变 `tools.jackson`）；
- **3.5.x** 已于 2026-06-30 停止开源支持（EOL），最后补丁 3.5.16；
- 两线都要求最低 Java 17。

## 决策

**选 Spring Boot 3.5.16**，接受「EOL 无官方补丁」的代价。

## 理由（按权重排序）

1. **生态兼容性**：MyBatis-Plus 对 Boot 4 的稳定支持要 3.5.15+ 才解决（3.5.14 直接报 `No qualifying bean`）；knife4j 对 Boot 4 的兼容性当时查不到明确结论 —— 对没人带的新手，文档工具装不上是致命的。
2. **资料覆盖**：教程、面经、Stack Overflow 答案绝大多数基于 2.x/3.x；Boot 4 的 lambda-only DSL、新 starter 命名会让抄来的代码编译不过，排查成本全压在自己身上。
3. **面试对齐**：企业存量最大仍是 3.x 甚至 2.x，面试官的问题语境大概率是 3.x。
4. **学习目标**：本项目学的是「分层、事务、ORM、鉴权」这些与版本弱相关的思想，版本新旧不影响学习收益。

## 代价与对冲

| 代价 | 对冲 |
|---|---|
| 无安全补丁 | 实习作品不处理真实敏感数据；上线仅演示数据 |
| 将来工作遇到 Boot 4 有陌生感 | 在本文记录 Boot 4 的三大差异（Jackson 3 / lambda DSL / starter 改名），面试被问能答 |
| 被动升级时跨度大 | 迁移路径：先升 MP/knife4j 到兼容版本 → 再升 Boot → 跑集成测试兜底 |

## 面试话术（30 秒）

> 「我知道 3.5 已经 EOL。选它是因为 MyBatis-Plus 和 knife4j 对 Boot 4 的兼容性当时不稳定，而我更看重生态和资料覆盖。如果这是要跑三年的生产系统，我会选 4.1 并预算生态适配成本 —— 技术选型没有标准答案，只有和约束匹配的答案。」
