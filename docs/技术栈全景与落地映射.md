# 技术栈全景：每个部件到底支持了哪里

> 创建日期：2026-10-04  
> 适用版本：前端 `my-h5-app` / 后端 `my-h5-api`  
> 阅读方式：横向看「谁负责什么」，纵向看「没有谁会怎样」。所有路径都指向真实文件，可对照阅读。

---

## 零、一句话总览

这是一个**前后端分离的两个独立仓库**项目：

- `my-h5-app`：浏览器里跑的一切。Vue 写界面，Pinia 存数据，axios 发请求，Vite 负责「翻译成浏览器能直接跑的代码」并提供开发服务器。**最终产物是一堆静态文件**（HTML + JS + CSS）。
- `my-h5-api`：跑在服务器上的 Node 程序（Express 框架），对外开 3000 端口，只负责收请求、查数据、返回一个统一形状的 JSON。

两者唯一的联系方式是 **HTTP 接口**（约定好的 URL 路径 + 方法 + 返回格式）。它俩之间**没有任何共享代码**，改后端不需要重新构建前端，这就是「前后端分离」的意义。

## 一、它俩怎么拼起来：从点开页面到看见数据

| 步骤 | 谁登场            | 具体动作                                              | 对应文件                                             |
| -- | -------------- | ------------------------------------------------- | ------------------------------------------------ |
| 1  | **浏览器**        | 打开 `localhost:5173`，下载 index.html                 | `index.html`                                     |
| 2  | **Vite**       | 把 `/src/main.ts` 编译后喂给浏览器，并在文件改动时自动刷新页面（HMR，热更新）  | `vite.config.ts`                                 |
| 3  | **Vue**        | `createApp(App)` 创建应用实例，挂到 `#app` 这个 div 上        | `src/main.ts`                                    |
| 4  | **Vue Router** | 读地址栏 `#/` 后面的路径，决定渲染哪个页面组件                        | `src/router/index.ts`                            |
| 5  | **生命周期钩子**     | 页面挂载完成（`onMounted`，组件被放进页面的瞬间触发）调用 store 加载数据     | `src/views/standings/StandingsList.vue`          |
| 6  | **Pinia**      | store 置 `loading = true`，页面据此显示骨架屏                | `src/stores/standings.ts`                        |
| 7  | **axios**      | 通过 `get()` 发出 HTTP 请求 `/api/standings`            | `src/api/request.ts`                             |
| 8  | **Vite 代理**    | 开发期把 `/api/*` 转发给 `localhost:3000`，并去掉 `/api` 前缀  | `vite.config.ts` 的 `server.proxy`                |
| 9  | **Express**    | 匹配到 `router.get('/standings')`，执行处理函数             | `my-h5-api/src/routes/standings.ts`              |
| 10 | **后端返回**       | `res.json({ code: 0, message: '', data: [...] })` | 同上                                               |
| 11 | **响应拦截器**      | 校验外壳合法后撕掉外壳，只把 `data` 交出去                         | `src/api/request.ts`                             |
| 12 | **运行时校验**      | 逐字段检查类型、检查必须 20 条，通过后才敢当 `TeamStanding[]` 用       | `src/api/standings.ts` + `src/utils/validate.ts` |
| 13 | **store 更新**   | 数据写进 `ref`， computed 自动重算，页面自动重渲染                 | `src/stores/standings.ts`                        |
| 14 | **Vue 渲染**     | 数据变化 → 虚拟 DOM 对比差异 → 只更新真正变了的 DOM 节点              | Vue 内部                                           |

> 第 13 步为什么是「自动」的：Vue 的响应式系统会记录「哪些计算用到了哪些数据」，数据一变，用到它的地方自动重新计算。这就是它和 jQuery 时代手动 `$('#id').html(...)` 的根本区别。

## 二、分层卡片：谁管什么 + 抽掉会怎样

### ① 页面层 `src/views/**/*.vue`

| 项          | 内容                                                                                    |
| ---------- | ------------------------------------------------------------------------------------- |
| **支撑技术**   | Vue 3 组件、组合式 API（`<script setup>`：把 JS 逻辑写在这个标签里的现代写法）、`scoped`（样式作用域隔离） CSS、Vant 组件库 |
| **它负责**    | 长什么样、响应用户点击、把状态翻译成界面                                                                  |
| **它禁止**    | 直接出现 `axios`、写业务逻辑、自己定义接口地址                                                           |
| **为什么这么禁** | 页面是全项目改动最频繁的文件。请求逻辑若长在这里，改版时会被顺手删掉；收在 api 层，页面随便换皮，数据管道原地不动                           |
| **抽掉会怎样**  | 没有界面，项目不存在                                                                            |

**Vant 在这里做了什么**：提供 `<van-pull-refresh>`（下拉刷新容器）、`<van-skeleton>`（骨架屏）、`<van-empty>`（空态/错误态）、`<van-button>` 等成品组件。没有它，这些交互控件你要手写几百行触摸事件处理。

### ② 状态层 `src/stores/*.ts`

| 项         | 内容                                                                                                            |
| --------- | ------------------------------------------------------------------------------------------------------------- |
| **支撑技术**  | Pinia（Vue 官方状态管理库，类似 React 生态的 Redux）                                                                         |
| **它负责**   | 保管跨组件共享的数据 + **列表三态**（`loading` 首次加载中 / `error` 失败原因 / `refreshing` 刷新中）+ 用 `computed`（计算属性，依赖不变就不重算，有缓存）派生数据 |
| **它禁止**   | 出现 DOM 操作、出现 URL（那是 api 层的事）                                                                                  |
| **抽掉会怎样** | 数据得靠组件间层层传参（props 逐层透传），两个页面要看同一份数据就得各请求一次，缓存和状态同步会彻底失控                                                       |

### ③ 接口层 `src/api/*.ts`

| 项                  | 内容                                                                                  |
| ------------------ | ----------------------------------------------------------------------------------- |
| **支撑技术**           | TypeScript 泛型 + `utils/validate.ts`                                                 |
| **它负责**            | 定义「有哪些接口」、把**不可信的后端原始数据**转换成**可信的业务类型**                                             |
| **核心写法**           | `get<unknown>()` → 逐字段 parse 校验 → 返回 `Promise<TeamStanding[]>`                      |
| **为什么泛型写 unknown** | 写成 `get<TeamStanding[]>` 等于口头无条件信任后端；TS 的类型编译完就消失了，运行时根本拦不住。先承认「我不知道它长什么样」，检查通过再贴标签 |
| **抽掉会怎样**          | 后端少返回一个字段 / 类型变成字符串，页面要么白屏要么显示 `undefined`，且极难定位                                    |

### ④ 传输层 `src/api/request.ts`

| 项                        | 内容                                                                                                 |
| ------------------------ | -------------------------------------------------------------------------------------------------- |
| **支撑技术**                 | axios（HTTP 客户端库）+ 拦截器（interceptor：请求发出前 / 响应回来后统一插手处理的地方）                                          |
| **它负责**                  | 五件全局规矩，全项目只写一次：① `baseURL` 从环境变量读；② 10 秒超时；③ 自动带 token；④ 撕掉 `{code,message,data}` 外壳；⑤ 非 0 业务码统一抛错 |
| **为什么只允许存在这一个 axios 实例** | 「唯一出口」才能保证规矩自动生效。若各页面自己 new，改一处忘一处                                                                 |
| **抽掉会怎样**                | 每个请求都要手写超时、手写错误处理，且永远会漏                                                                            |

### ⑤ 工具层 `src/utils/validate.ts`

| 项         | 内容                                                                                          |
| --------- | ------------------------------------------------------------------------------------------- |
| **支撑技术**  | 零依赖纯函数 + 类型守卫（`raw is Record<string,unknown>`：告诉 TS「通过检查后它是什么类型」的返回值写法）                     |
| **它负责**   | 弥补 **TypeScript 类型擦除**（类型只在写代码和编译时存在，浏览器运行时一行不剩）带来的真空                                       |
| **两种力度**  | 严格 `asNumber(x, '点')` 类型错就抛错；宽松 `asNumber(x, '点', 0)` 用兜底值。业务核心数据（积分、金额）严格，次要展示字段（队徽 URL）宽松 |
| **抽掉会怎样** | 后端数据出错时前端静默显示怪值，排查要抓包到天亮                                                                    |

### ⑥ 契约层 `src/types/api.ts`

| 项          | 内容                                      |
| ---------- | --------------------------------------- |
| **支撑技术**   | TypeScript `interface`（接口，只描述形状，运行时不存在） |
| **它负责**    | 做前后端的「契约镜像」，尤其是统一响应外壳 `ApiResponse<T>`  |
| **一个关键约定** | 这里的类型描述的是 **parse 归一化之后的形状**，不是后端返回原文   |
| **抽掉会怎样**  | 失去唯一权威定义，各处凭记忆写字段名                      |

### ⑦ 样式层 `index.css` + `scoped` + `responsive.css`

| 项         | 内容                                                                                             |
| --------- | ---------------------------------------------------------------------------------------------- |
| **支撑技术**  | CSS + PostCSS（CSS 的编译处理流水线，插件在这里改写 CSS）+ `postcss-px-to-viewport-8-plugin`                     |
| **它负责**   | ① 基础重置与主题变量；② 组件级样式隔离（Vue 给元素打随机属性 `data-v-xxxx`，同名 class 不再互相污染）；③ 手机等比缩放 + PC 重排版（见 ADR-002） |
| **抽掉会怎样** | 手机列宽各异、PC 上被放大 5 倍；多人协作样式互相覆盖                                                                  |

### ⑧ 后端 `my-h5-api/src/`

| 项          | 内容                                                                                                                         |
| ---------- | -------------------------------------------------------------------------------------------------------------------------- |
| **支撑技术**   | Express 5（Web 框架）、cors（跨域中间件）、express.json（请求体 JSON 解析中间件）、tsx（直接运行 TS 的运行器，省去手动编译步骤）                                      |
| **它负责**    | 监听 3000 端口 → 经过中间件流水线 → 按「路径 + 方法」匹配路由 → 返回统一外壳 JSON                                                                       |
| **中间件是什么** | 请求进入路由前依次经过的处理站。`cors()` 加跨域响应头，`express.json()` 把请求体字符串解析成对象——**没有它，`req.body` 永远是 undefined**（第 2 周写 POST 接口时你会第一次真切感受到） |
| **抽掉会怎样**  | 前端无数据来源                                                                                                                    |

## 三、把项目跑起来，到底需要哪些东西

这是「跑一遍的最小要素清单」，缺任何一个都起不来：

| 要素                      | 作用                                           | 少了会怎样                   |
| ----------------------- | -------------------------------------------- | ----------------------- |
| **Node.js**             | JS 运行时。浏览器之外的另一个「能跑 JS 的地方」                  | 一切免谈                    |
| **npm**                 | 包管理器：按 `package.json` 下载依赖到 `node_modules`   | 拿不到第三方库                 |
| **`package-lock.json`** | 锁定每个依赖的确切版本                                  | 两人装出不同版本，出现「我这儿好的你那儿不行」 |
| **`index.html`**        | 唯一的 HTML 入口，含 `<div id="app">` 和 viewport 配置 | 手机端所有适配的地基没了            |
| **`src/main.ts`**       | 装配现场：注册 Pinia、Router、Vant，按顺序加载三个 CSS        | 插件未注册，组件报错              |
| **`.env.development`**  | 定义 `VITE_API_BASE_URL=/api`                  | 请求打到页面自身地址              |
| **`vite.config.ts`**    | 路径别名 `@`、代理转发、px→vw 插件                       | 深层相对路径满天飞；开发期跨域报错       |
| **Vite 开发服务器**          | `npm run dev` 起在 5173，提供编译 + 热更新 + 代理        | 每次改代码要手动刷新，且必然跨域失败      |
| **后端进程**                | `npm run dev` 起在 3000                        | 前端请求全部失败（ECONNREFUSED）  |
| **两个终端/进程**             | 前后端是两个独立程序                                   | ——                      |

**注意最后一个条目**：这两个进程**互不感知**。你在前端页面上看到数据加载失败，**第一件要做的事是确认后端 3000 端口还活着**——浏览器访问 `localhost:3000/health` 一秒验证。这是最常见的「假故障」。

### 命令对照

| 命令                                | 作用                                                     |
| --------------------------------- | ------------------------------------------------------ |
| `npm run dev`                     | 起开发服务器（5173），带热更新                                      |
| `npm run build`                   | 先类型检查（`vue-tsc`）再打包到 `dist/`，产出静态文件                    |
| `npm run preview`                 | 本地预览 `dist/` 打包结果（**注意端口是 4173，不是 5173**），用于验证上线后的真实表现 |
| `npm run type-check`              | 只做类型检查，不产出文件                                           |
| `npm run lint` / `npm run format` | ESLint 找代码问题 / Prettier 统一格式                           |

> `dev` 和 `preview` 的区别常被混淆：`dev` 跑的是源码 + 开发服务器（有代理、有热更新，但不代表上线后的样子）；`preview` 跑的是**打包产物**（这才是用户真正拿到的东西，`?route=` 只有在 `dist` 生成后才能预览）。

## 四、术语速查（按出现顺序）

| 术语                    | 人话解释                                                                                                                                    |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| SPA（单页应用）             | 整个网站其实只有一个 HTML，页面切换是 JS 在本地换内容，**不向服务器要新页面**。配合 hash 路由（`#/standings`），服务端不需要任何路径重写配置                                                  |
| CSR（客户端渲染）            | HTML 一开始是空的，数据在浏览器里才被取回并画上去。代价：首屏有一段白屏期 + 搜索引擎抓取不到内容（要做 SEO 就得上 SSR，服务端渲染，届时技术栈会变）                                                      |
| HMR（热更新）              | 改完代码保存，浏览器**不刷新整页**就替换掉变了的那个组件。Vite 快是因为它按需编译 + esbuild 预构建                                                                             |
| 代理 / proxy            | 开发期的「中转站」。浏览器有同源策略（只能请求同协议同域名同端口的地址），而 Vite 的开发服务器是 Node 程序，**不受浏览器同源策略约束**，所以由它转发。生产环境没有这个服务器，要用 CORS（跨域资源共享，后端装 cors 中间件加响应头）或前后端同域部署 |
| 中间件                   | Express 里请求要经过的一串处理站，每站都能改写请求或提前返回响应                                                                                                    |
| 拦截器                   | axios 版的中间件，分请求拦截（发出前改 config）和响应拦截（回来后处理数据）                                                                                            |
| Promise / async-await | 异步（不阻塞后续代码的操作）结果的容器。`await` 会冻结当前函数的现场，让出 CPU，等结果回来再接着往下跑——**注意它冻结的是这个函数，不是整个程序**                                                       |
| 类型擦除                  | TypeScript 的类型信息在编译成 JS 后被完全删掉，浏览器运行时不知道任何类型存在                                                                                          |
| 类型守卫                  | 一个返回布尔值的函数，但告诉 TS「返回 true 意味着参数是什么类型」，让 TS 自动收窄类型，`any` 做不到这点                                                                           |
| 泛型 `<T>`              | 类型的「参数」。`get<T>(url): Promise<T>` 意思是：调用方填什么类型，返回就是什么。但它只是一句承诺，靠不住（所以要运行时校验兜底）                                                          |
| tree-shaking          | 打包时自动删掉没被引用的代码。按需引入 UI 库后体积减半靠的是它                                                                                                       |
| 断点（breakpoint）        | 布局切换的临界屏幕宽度。本项目统一 768px，**只允许在这一个断点文件里定义**                                                                                              |
| 降级                    | 某项能力不可用时，退回到更简单但不会崩的表现。本项目有两处：队徽没图 → 显示排名圆圈；老 Safari 不认新式媒体查询 → 退回手机版布局                                                                 |

## 六、两条贯穿始终的红线

1. **依赖方向只能自上而下**：`views → stores → api → utils`。下层永远不知道上层存在。这条约束换来的核心好处是：**换 UI（重做页面）不会碰业务逻辑，换后端 URL 不会碰页面**。
2. **凡是不能百分百确定的外部输入，进门时必须校验**：后端数据进了 `api/` 就要 parse，用户输入将来要在前后端各校验一次（前端为体验，后端为安全）。

第二条尤其重要——C 语言里指针传错地址会立刻崩溃给你看；Web 里一个类型不匹配可能只是「页面上少显示一行字」，安静地错很久才被发现。**这也就是为什么在这套架构里，`.ts` 类型之外还要额外留一层运行时校验。**
